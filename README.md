# The Witness 谜题助手

> 🚀 **[在线体验](https://youarer1ght.github.io/TheWitnessPuzzle/)** — 无需下载，直接在浏览器中使用
>
> 一个交互式 Web 工具，帮助理解和解决《The Witness》游戏中的画线谜题。
>
> 规则参考：[《The Witness》设计研究笔记](https://zhuanlan.zhihu.com/p/444254269) 及游戏 Wiki。

## 功能特性

- 🎮 **交互式棋盘**：点击/拖拽画线，直观的可视化操作
- 🧩 **完整符号支持**：六边形、圆角方块、星形、俄罗斯方块、三角形、消除标记
- 🤖 **自动求解**：内置 BFS + 回溯算法，可独立解出谜题
- ✅ **实时规则验证**：绘制过程中实时检查路径是否符合所有谜题规则，精确提示错误位置
- 📚 **预设谜题**：内置 30+ 道谜题，按主题分组（入门、六边形、方块、星形、俄罗斯方块、三角形、消除、对称、边缘六边形、综合挑战）
- 🎨 **游戏风格**：暗色主题，模仿原游戏面板风格

## 快速开始

**方式一（最直接）：** 双击 `index.html` 在浏览器中打开。

**方式二（本地服务器）：**

```bash
cd the_witness
npx serve . -p 8765
```

然后访问 <http://localhost:8765>

## 谜题规则详解

> 以下规则整理自 [《The Witness》设计研究笔记](https://zhuanlan.zhihu.com/p/444254269) 及游戏 Wiki。

### 题板的基本构成

一块基本题板由以下部分组成：

| 元素 | 说明 |
|------|------|
| **起点** | 圆形，路线从此开始；一块题板可能有多个起点 |
| **终点** | 半圆形，路线在此结束；可能有多个终点 |
| **通道** | 可以划线的路径（网格的边） |
| **间隔** | 不能划线的块状区域（网格的格子） |
| **分割区域** | 划线将题板分割成的若干封闭连通区域 |
| **边界** | 题板边缘，作为天然的"墙" |

### 起点和终点的位置

起点和终点可以放置在以下两种位置：

#### 1. 网格节点（交点）

起点/终点放置在网格线的**交叉点**上——这是最常见的放置方式。

- **起点在节点上**：路径从此节点开始，初始状态下终点标记已在该节点上
- **终点在节点上**：路径的最后一个节点必须恰好是终点所在的节点

#### 2. 边缘中点

起点/终点也可以放置在网格方块某条边的**中点**位置（即两个相邻节点之间的中点）。

- **起点在边缘中点**：路径从该中点出发，第一步必须走向该边两端的**任一相邻节点**
  - 路径初始为空 `[]`，用户选择走向哪个节点决定了路径的起始方向
  - 从边缘中点出发后，后续行为与节点起点完全一致
  
- **终点在边缘中点**：路径的最后一个节点必须是该边两端的**任一相邻节点**
  - 即走到终点边缘的任意一端即视为到达终点

> 📌 **为什么要有边缘中点？** 《The Witness》游戏中许多谜题将起点/终点放置在面板边缘的中点位置（而非角落节点），这增加了谜题的变化和难度。本工具完整支持这两种放置方式。

> 🎨 **如何放置？** 从左侧面板拖拽「🟢 起点」/「🔴 终点」按钮到网格上的任意位置——拖到**节点（交叉点）**即放置为节点起点/终点，拖到**边缘中点**即放置为边缘起点/终点，自动识别。放置后同样支持拖拽移动、跨类型拖放（节点⇄边缘）以及拖到回收区删除。

**渲染效果：**
- 边缘中点的起点/终点与节点上的起点/终点外观一致（圆形/半圆形）
- 路径会显示从边缘中点到第一个节点的线段（起点），以及最后一个节点到边缘中点的线段（终点）
- 路径有效性验证会自动检查起点/终点的相邻关系

#### 多起点和多终点

《The Witness》中一块题板可以有**多个起点和多个终点**，本工具完整支持：

- **多起点**：可在多个节点 / 多条边缘中点上放置起点符号。用户可从**任意一个起点**开始画线。
  - 节点起点：**点击该节点**开始追踪
  - 边缘中点起点：点击边缘中点（**自动吸附**到最近的相邻节点）开始追踪
  - 存在多个起点时，路径初始为空（不预设起点），由用户**点击选择**从哪个起点出发
  - **切换起点**：如果已有路径，点击另一个有效的起点位置会清空旧路径并从新起点重新开始

- **多终点**：可在多个节点 / 多条边缘中点上放置终点符号。路径到达**任意一个终点**即视为完成。
  - 节点终点：路径最后一个节点必须恰好是该节点
  - 边缘中点终点：路径最后一个节点必须是该边缘的任一相邻节点

- **任意组合**：可从任意起点出发，到达任意终点（无需配对）
  - 例如：2个节点起点 + 3个边缘起点 → 可以从这5个起点中的任意一个开始
  - 例如：1个节点终点 + 2个边缘终点 → 到达这3个终点中的任意一个即算完成

> 🎮 **操作技巧**：点击边缘中点上的起点符号时，系统会自动吸附到最近的相邻节点开始追踪。你也可以直接点击相邻节点开始。

### 核心操作

从**圆形起点**开始画线，画出路线连接到**半圆形终点**。路径沿网格边移动，不可重复经过同一节点。路径与棋盘边界共同将棋盘划分为多个**连通区域（分割区域）**。

> 💡 **多起点/多终点**：存在多个起点时，可从任意一个出发；存在多个终点时，到达任意一个即算完成。详见上方「多起点和多终点」。

### 一、通道阻断

在间隔之间或间隔与边界之间增加不可通行的隔断（断开的边）。路径不可穿越隔断。

> 📌 在本工具中，**直接在画布上点击要隔断/连通的边的中点**即可切换该边的阻断状态（再次点击恢复连通）。无需工具按钮，也不影响画线：节点附近点击属于画线，边中点附近点击属于隔断。

### 二、六边形（Hexagon）— 必经节点/边

| 属性 | 说明 |
|------|------|
| **位置** | 网格**节点**（交叉点）**或边中点**，与起点/终点的放置方式相同 |
| **规则** | 划线必须**经过每一个六边形**才能到达终点 |
| **节点六边形** | 路径必须**穿过该节点** |
| **边缘六边形** | 路径必须**走过那一条边**（经过该边中点） |
| **颜色** | 黑色：任意颜色的线都可经过；蓝色/黄色：仅对应颜色的线可经过（对称谜题） |

---

### 三、圆角方块（Square）— 颜色隔离

| 属性 | 说明 |
|------|------|
| **位置** | 间隔（格子）内部 |
| **规则** | 划线必须将**不同颜色**的圆角方块分隔到不同的连通区域中 |

**关键理解：**
- 同一颜色的方块可以分散在多个不同区域中——只要每个区域内部不混入异色方块即可
- 棋盘边界也算作分隔"墙"
- 规则是**按区域分隔**，而非按边分隔
- 多色方块（温室/地堡区域）遵循同样规则，只是颜色种类更多
- **没有数量/偶数限制**：圆角方块不需要成对，任意数量（1、3、5…）的同色方块都合法
- **黑、白方块与其它颜色一视同仁**：黑白是两种不同的颜色，同一区域混入黑白、或黑/白与其它颜色同样违规；不存在黑白被特殊对待的豁免

> 📌 不是简单的"黑白分开"，而是"同一区域内不能有不同颜色共存"。

---

### 四、星形符号（Star/Sun）— 同色配对

| 属性 | 说明 |
|------|------|
| **位置** | 间隔（格子）内部 |
| **规则** | 区域内**存在某色星形**时，该色符号（星形 + 同色圆角方块）总数必须**恰好为 2** 个；区域内没有该色星形时无此约束 |

**关键理解：**
- 星形是配对的**触发者**：一个区域内必须恰好有 2 个同色星形才能成对
- 同色圆角方块**仅在与星形同处一个区域时**才可充当配对对象（1 星 + 1 同色方块 = 有效的一对）
- 区域内没有星形的圆角方块**不参与配对**，只遵循「颜色分离」规则（见第三节）
  - 例：两个橙色星形同区 + 一个粉色方块同区 → 粉色方块没有配对约束，仅做颜色分离即可
- 本规则对**所有颜色一视同仁**：包括黑、白在内的任何颜色方块都只在「与同色星形同区」时才参与配对，不存在黑白被特殊对待的例外
- 不同颜色的配对互不干扰（橙色星与橙色星配对，紫色星与紫色星配对）
- 如果同一区域内有 3 个同色星形，则无法满足规则（非偶数）；4 个需要分成两个区域，每区 2 个

---

### 五、俄罗斯方块（Tetris / 多联骨牌）— 形状匹配

| 属性 | 说明 |
|------|------|
| **位置** | 间隔（格子）内部 |
| **规则** | 符号所在分割区域的形状必须**恰好等于**方块形状的组合（可平移，不可重叠） |

**详细规则：**

| 情况 | 规则 |
|------|------|
| **水平摆放**（非倾斜 `tilted=false`） | 形状和角度必须**完全相同**，不可旋转 |
| **倾斜摆放**（`tilted=true`） | 形状相同即可，**可以旋转但不能翻转/镜像** |
| **多个方块在同一区域** | 可以组合拼接；**构想阶段允许重叠**（因蓝色空心方块会做减法），**减法后必须恰好填满不重叠** |
| **黄色实心方块** | 正形状——区域必须包含这些格子 |
| **蓝色空心方块** | 负形状（减法）——从黄色形状中**减去**对应格子，**直接改变区域轮廓**。实心形状可延伸到区域外，被空心方块抵消的部分不计入区域 |

**方块拟合说明：**
> 多方块拼接时，方块之间可以在构想中重叠（因为蓝色空心方块会从重叠区域减去）。验证算法会先放置所有实心方块（允许延伸到区域外），再放置空心方块（无锚点约束，可放在任意位置抵消延伸部分），最终检查剩余形状是否恰好填满区域。**空心方块直接缩小所需的区域大小：例如3格实心方块+1格空心方块，只需2格大小的区域。**

**特殊规则——全抵消：**
> 如果某个区域内**蓝色空心方块的数量 == 黄色实心方块的数量**，则该区域的形状不再重要——无论形状如何都算正确。
>
> 📌 空心方块是俄罗斯方块系统内的**减法运算**，与消除标记（倒Y符号）完全无关。消除标记取消的是规则违规而非方块格子，详见第七节。

### 六、三角形（Triangle）— 边数约束

| 属性 | 说明 |
|------|------|
| **位置** | 间隔（格子）内部 |
| **规则** | 该间隔周围的通道（边）被路径**经过的次数**必须等于三角形数量 |

- **1 个三角形** → 恰好 1 条边被路径经过
- **2 个三角形** → 恰好 2 条边被路径经过
- **3 个三角形** → 恰好 3 条边被路径经过

> 📌 注意：此符号在游戏正式版中已被弃用（Deprecated），部分相关题板以彩蛋形式存在于环境中。

### 七、消除标记（Elimination / 倒Y / 三叉符号）— 消除违规符号

| 属性 | 说明 |
|------|------|
| **位置** | 间隔（格子）内部 |
| **规则** | 消除标记必须**消除其所在分割区域内「一个条件未被满足的符号」（自身除外）**——即逐符号消除，而不是抹平整条规则 |

**关键理解：**
- **逐符号消除**：每个消除标记只消除一个违规的符号（被消除的符号视为不存在，其规则约束随之消失）；消除后该区域必须恢复合法
- **不同规则需要消除的符号数（代价）不同**：
  - **圆角方块混色**：需要消除 `总方块数 - 最多颜色方块数` 个方块（消除到只剩一种颜色）
    - 例：区域内 2 黑 + 2 白 → 需消除 2 个才能只剩一种颜色 → **1 个消除标记无法修复**
    - 例：区域内 2 橙 + 1 粉 → 消除 1 个粉色方块即可只剩橙色 → 1 个消除标记可修复
  - **星形配对错误**：总数 > 2 时需消除 `总数 - 2` 个；总数 = 1 时消除 1 个（消除后该色无星形，配对约束不再适用）
  - **俄罗斯方块不匹配**：需消除 `总方块数 - 最大合法子集` 个（找出能恰好填满区域的方块子集，其余全部消除）
  - **三角形边数错误**：每个违规三角形需消除 1 个
- 消除标记可以消除**任意类型**的违规符号（方块、星形、俄罗斯方块、三角形），只要该符号与消除标记在同一区域内
- 如果消除标记所在区域**没有任何可消除的违规符号**，则该标记自身成为一个违规
- 消除标记**不能互相消除**（不能用一个消除标记消除另一个消除标记）
- 消除标记不能消除路径级别的错误（起点/终点、对称性等），只能作用于区域级别
- 多个消除标记在同一区域时，**每个各自消除一个违规符号**；若消除标记数量超过可消除的违规符号数量，多余的消除标记自身报错

> 📌 **与蓝色空心方块的关键区别：** 消除标记消除的是**具体违规的符号**，蓝色空心方块是俄罗斯方块系统内的**减法运算**（从实心形状中减去格子数）——两种完全不同的机制，互不相关。空心方块详见第五节。

## 规则的设计哲学

游戏规则具有极强的**正交性**：每条规则精炼独立、不冗余、不互斥。例如：

- 颜色隔离规则（方块）+ 星形配对规则 → 两条规则必须**同时满足**
- 六边形经过规则 + 方块隔离规则 → 路径既要经过所有六边形，也要正确分隔颜色

正是这种正交性加上规则的组合能力，使得简单的符号可以拼装出无比紧凑的高难度谜题。

## 操作说明

### 画线
| 操作 | 效果 |
|------|------|
| **左键点击节点** | **切换追踪模式** — 第一次点击开始追踪，路径自动跟随鼠标沿边缘移动；再次点击停止追踪 |
| **鼠标移动（追踪中）** | 路径自动延伸至鼠标经过的合法相邻节点；鼠标回到上一节点时自动撤销 |
| **右键 / Backspace** | 撤销最后一步 |

### 编辑符号

**拖拽放置（推荐）：**
- **从左侧拖到画布**：按住编辑工具按钮，拖拽到画布目标位置松开即可放置符号
- **拖拽删除**：按住画布上已有的符号，拖拽到右下角回收区 🗑️ 即可删除

**点击放置（备选）：**

- **起点 / 终点**：放置或移动起点/终点。拖到**节点**为节点起点/终点，拖到**边缘中点**为边缘起点/终点（自动识别，详见上方「起点和终点的位置」说明）
- **六边形**：放置在节点或边缘中点（自动识别）的必经标记
- **黑/白方块**：在格子中放置颜色方块
- **星形**：在格子中放置配对符号
- **三角形**：在格子中放置边数约束
- **消除标记**：放置通配符
- **隔断**：在边上设置/取消不可通行阻断。**直接点击要隔断/连通的边的中点**即可切换（再次点击恢复连通）；节点附近点击属于画线，互不干扰

### 求解
| 按钮 | 效果 |
|------|------|
| **🤖 自动求解** | AI 搜索**全部解答**（最多100个）。多起点/多终点会产生多条不同路径，不同路径导致不同区域划分，影响方块/星形配对等规则判定 |
| **▶ 演示答案** | 逐步动画展示当前选中解答的求解结果 |
| **◀ 上一个** | 切换到上一个解答（多解时可用） |
| **下一个 ▶** | 切换到下一个解答（多解时可用） |
| **📋 导出调试信息** | 一键导出完整谜题状态（棋盘规格、符号、路径、求解结果）为 JSON 文件 |

> 💡 **全部解**：多起点/多终点的谜题可能有多条合法路径。求解器会找到所有解并在状态栏显示总数（如"共16个解"）。使用「上一个」「下一个」按钮可浏览所有解，每个解都可以独立演示。

## 调试与反馈

当你在网页端遇到无法正确求解的谜题，或对求解结果有疑问时，可以使用内置的调试工具快速反馈问题。

### 一键导出调试信息

1. 在网页右侧面板点击 **📋 导出调试信息** 按钮
2. 浏览器会自动下载一个 JSON 文件，文件名格式为 `witness_debug_<行>x<列>_<对称>_<时间戳>.json`

**导出内容包括：**

- 棋盘规格（行列数、对称设置）
- 所有符号（起点、终点、六边形、方块、星形、俄罗斯方块、三角形、消除标记、隔断）
- 玩家当前绘制的路径
- 求解器找到的所有解
- 玩家路径的验证结果（包含具体错误信息）

### 本地分析工具

使用 Node.js 脚本对导出的 JSON 文件进行离线验证：

```bash
# 分析单个文件
node debug_tool.js witness_debug_4x4_diagonal_2026-08-09.json

# 批量分析目录下所有导出文件
node debug_tool.js --batch ./debug_exports/

# 查看帮助
node debug_tool.js --help
```

**本地工具会检查：**

| 检查项 | 说明 |
| ------ | ---- |
| 数据格式 | JSON 结构是否完整 |
| 符号统计 | 各类符号的数量是否正确 |
| 玩家路径 | 路径是否合法（相邻性、不重复、不跨越隔断、起终点正确） |
| 求解器结果 | 每个解的路径是否通过基本合法性检查 |
| 对称性 | 对称模式下镜像路径是否正确，主路径与镜像路径是否有边/节点冲突 |
| 综合结论 | 汇总所有检查项，给出通过/失败/需注意的结论 |

### 反馈流程

```text
网页端遇到问题
    │
    ├─ 实时状态栏显示具体违反的规则（无需手动点击）
    │
    └─ 点击"📋 导出调试信息" → 下载 JSON 文件
            │
            └─ 本地运行 debug_tool.js 分析
                │
                └─ 将 JSON 文件和终端输出一起反馈
```

> 💡 **提示**：导出的 JSON 文件可以直接用文本编辑器打开查看，也可以附加到 Issue 或反馈中，方便定位问题。

## 技术实现

- 纯 HTML/CSS/JavaScript，无框架依赖
- Canvas API 渲染棋盘和符号
- BFS 算法处理六边形类谜题（复杂度 O(N × 2^H)）
- 回溯搜索 + 约束传播处理区域约束类谜题
- 泛洪填充（Flood Fill）算法进行区域检测
